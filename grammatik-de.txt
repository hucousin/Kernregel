/|
| Kernregel(.kr) Sprachgrammatik‑Beispiele
| C++ VM‑Typ
| Die auskommentierten Codes können nach Entfernen der Kommentare verwendet werden (sie sind nur bei Tests auskommentiert, um überflüssige Ausgaben zu vermeiden)
| Funktions‑ und Variablennamen unterstützen Unicode‑Zeichen
| Halten Sie sich zur einheitlichen Syntax möglichst an die voreingestellten Schlüsselwörter, vermeiden Sie optionale Schlüsselwörter
| Kr unterstützt die Einrückungssyntax (jede Einrückung größer als die des übergeordneten Blocks ist gültig), halten Sie den Stil konsistent; wenn der übergeordnete Block geschweifte Klammern verwendet, müssen untergeordnete Blöcke ebenfalls Klammern verwenden, sonst kommt es zu Syntaxfehlern; lexikal unterstützt keine Einrückungssyntax (Präprozessor duldet keine Mehrdeutigkeiten)
| Kr nutzt Funktionsgültigkeitsbereiche; die Iteration „für jedes“ erzeugt einen neuen lokalen Gültigkeitsbereich, andere Schleifenanweisungen nicht.
| Abgesehen von Speicheroperationen ist jeder Kern‑Code gültiger Kernregel‑Code, Ausführungsergebnisse sind nahezu identisch, die interne Logik unterscheidet sich jedoch deutlich
| Es gibt Visual‑Studio‑Code‑Syntax‑Hervorhebung sowie lexikal‑basierte semantische Hervorhebungs‑Erweiterungen; die semantische Hervorhebung ruft bei Bedarf den Kr‑Interpreter auf, um AST‑ und Lexik‑Informationen abzurufen und Fehlermeldungen sowie Detailinformationen zu Bezeichnern bereitzustellen
|
| Ohne Optimierung: Leere Schleife mit einer Million Iterationen dauert ca. 4 ms; Schleife mit einer Inkrement‑Anweisung im Rumpf ca. 17 ms, entspricht etwa hundert Millionen VA‑Schleifendurchläufen
| Warnung ab v0.0.19xx: Der VM‑Modus kann weniger stabil sein als der reine Interpreter‑Modus
|
| Projekt gestartet am: 2026.06.28

/|
| Beim Ausführen eines Kr‑Skripts können beliebig viele durch Leerzeichen getrennte Parameter hinter dem Skriptnamen übergeben werden.
| Diese werden automatisch in zwei globale schreibgeschützte Konstanten eingetragen:
|
|   arga  – Ganzzahl, Anzahl der übergebenen Parameter (ohne Programm‑ und Skriptdateiname)
|   argw  – String‑Array, jeder Eintrag entspricht einem übergebenen Parameter, Index beginnt bei 0
|
| Hinweis: arga und argw sind Konstanten, sie können nicht neu zugewiesen werden.
|
| Beispiel Befehlszeile: kr test.kr a b "c d"
| Dann gilt: arga = 3, argw = ["a", "b", "c d"], fname() = "test.kr"
|
| Lässt sich mit --opt kombinieren:
|   kr test.kr --opt "{haupt: main}" arg1 arg2
|   In diesem Fall wird main aufgerufen, arga und argw enthalten weiterhin arg1 und arg2.
|
| Beispielverwendung
|   fkt main() {
|       zeig "Skriptname: ", argw[0]
|       fa arga > 0 {
|           zeig "Erster Parameter: ", argw[1]
|       }
|       für i in 0..arga-1 {
|           zeig "argw[", i, "] = ", argw[i]
|       }
|   }
|/

// Die Handler‑Funktion erhält ein anfrage‑Objekt:

//   anfrage.pfad     - vollständiger Anfrage‑Pfad inklusive Query‑String

//   anfrage.inhalt   // unparsierter Anfrage‑Body‑String

// Die Handler‑Funktion muss ein Antwort‑Objekt zurückliefern:
//   { zustand: Statuscode, kopf: { … Antwort‑Header … }, inhalt: Antwort‑Body }
//
// eingebaute Konstruktor‑Funktionen für Antworten (setzen automatisch Content‑Type):
//   html(s [, status])        ‑ HTML‑Antwort (Content‑Type: text/html; charset=utf‑8)
//   json(v [, status])        ‑ JSON‑Antwort (Content‑Type: application/json; charset=utf‑8)

// Beispiel 1: einfacher HTTP‑Router mit GET‑Routen, Query‑Parametern
fkt handler(anfrage) {
    url    = anfrage.pfad
    params = abfrage(url)               // Query‑Parameter als Objekt
    qm     = url.stelleVon("?")
    pfad   = qm == -1 ? url : url.ab(0, qm)
    fa pfad == "/" {
        titel = params.titel ?? "Welt"
        gib html(`
            <!DOCTYPE html>
            <html lang="de">
            <head>
                <meta charset="utf‑8">
                <title>Kernregel</title>
                <style>
                    body { font‑family: sans‑serif; margin: 2em; }
                    h1   { color: #2a6; }
                    code { background: #eee; padding: 2px 4px; border‑radius: 3px; }
                </style>
            </head>
            <body>
                <h1>Hallo &{esc(titel)}!</h1>
                <p>Pfad: <code>&{esc(pfad)}</code></p>
                <p>Suche: <code>&{esc(params.suche ?? "—")}</code></p>
                <ul>
                    <li><a href="/daten?x=1&y=2">/daten?x=1&y=2</a> (JSON)</li>
                    <li><a href="/text?name=Max">/text?name=Max</a> (Klartext)</li>
                    <li><a href="/alt">/alt</a> (Weiterleitung → /)</li>
                </ul>
            </body>
            </html>
        `)
    }
    snfa pfad == "/daten" {
        gib json({
            pfad: pfad,
            parameter: params,
            zeit: zeit(),
            gefunden: wahr
        })
    }
    snfa pfad == "/text" {
        gib text("Hallo " ## (params.name ?? "Welt") ## "!\n")
    }
    snfa pfad == "/alt" {
        gib umleiten("/", 302)
    }
    sonst {
        gib html(`
            <h1>404 ‑ Nicht gefunden</h1>
            <p>Angefragt: <code>&{esc(url)}</code></p>
        `, 404)
    }
}
starteServer(8080, handler)

// Beispiel 2: Formular‑Verarbeitung mit POST‑Methode (PRG‑Muster)
fkt formHandler(anfrage) {
    fa anfrage.pfad == "/anmelden" und anfrage.methode == "GET" {
        gib html(`
            <form method="post" action="/anmelden">
                <p>Benutzer: <input name="benutzer"></p>
                <p>Passwort: <input name="passwort" type="password"></p>
                <button type="submit">Anmelden</button>
            </form>
        `)
    }
    snfa anfrage.pfad == "/anmelden" und anfrage.methode == "POST" {
        daten  = formular(anfrage.inhalt)
        nutzer = daten.benutzer ?? ""
        pass   = daten.passwort ?? ""
        fa nutzer == "" od pass == "" {
            gib text("Benutzername und Passwort erforderlich", 400)
        }
        fa nutzer == "admin" und pass == "geheim" {
            // PRG‑Muster: POST → Weiterleitung auf GET‑Seite, um Doppel‑Submit bei Aktualisierung zu verhindern
            gib umleiten("/willkommen?name=" ## kodierURL(nutzer), 303)
        }
        gib html("<p>Anmeldung fehlgeschlagen</p>", 401)
    }
    snfa anfrage.pfad == "/willkommen" {
        name = abfrage(anfrage.pfad).name ?? "Gast"
        gib html("<h1>Willkommen, &{esc(name)}!</h1>")
    }
    sonst {
        gib text("Nicht unterstützt", 405)
    }
}

// ============================================================================
// VSE‑Standard‑Architektur‑64‑Assembler‑Anbindung
// ============================================================================
// Variablenübergabe am besten über &{...}‑String‑Interpolation; direkte Variablenübergabe ist nicht nativer Bestandteil
// Code wird interpretiert, nutzt physikalische Register und führt Maschinen‑Code‑Befehle aus
// Unicode‑Bezeichner sind erlaubt
// Rückgabe‑Objekt erg = <--va--> ... <----> liefert {code: Quelltext, erg: Ergebniswert, fehl: Fehlermeldung, abnorm: boolescher Abbruch‑Flag}
// Aufruf als Bibliotheks‑Funktion: va(`...`)
<--va-->
; ============================================================================
; VSE Standard Architecture ‑ 64‑Bit‑Assembler (.va‑Quellcode)
; Kommentare beginnen mit Semikolon
; Projektbeginn: 2026‑08‑24
; ============================================================================
; ----------------------------------------------------------------------------
; Register‑Übersicht (Groß‑ / Kleinschreibung egal)
;   r1  = RAX   r2  = RCX   r3  = RDX   r4  = RBX
;   r5  = RSP   r6  = RBP   r7  = RSI   r8  = RDI
;   r9  = R8    r10 = R9    r11 = R10   r12 = R11
;   r13 = R12   r14 = R13   r15 = R14   r16 = R15
; ----------------------------------------------------------------------------
; ---------- Daten‑Definitionen ----------
msg:    db "Hallo Welt!", 0      ; Null‑terminierte Zeichenkette
puffer: dq 0, 0, 0, 0            ; 32‑Byte‑Datenpuffer für Speicherzugriff‑Beispiele
zahl:   dq 42                    ; 64‑Bit‑Ganzzahl‑Wert
hexwer: db 0xFF, 0x0A            ; zwei Byte‑Werte: 255 und 10
arr:    dd 1, 2, 3, 4            ; vier 32‑Bit‑Ganzzahlen
wort:   dw 0x1234                ; 16‑Bit‑Wert
; ---------- Programm‑Einstiegspunkt fest: _start ----------
_start:
    ; ---------- Daten‑bewegen der‑Befehl ----------
    der r1, puffer          ; r1 erhält die Laufzeit‑Adresse von puffer
    der r2, 100             ; Sofortwert in Register schreiben
    der [r1], r2            ; Speicher: *(int64*)r1 = 100
    der r3, [r1]            ; Speicher lesen: r3 = *(int64*)r1 → 100
    ; Speicherzugriff mit Offset
    der r2, 200
    der [r1+8], r2
    der r4, [r1+8]          ; r4 = 200
    ; ---------- Arithmetische Befehle ----------
    add r1, 3               ; r1 += 3
    sub r4, r2              ; r4 -= r2
    ink r1                  ; r1++ Inkrement
    dek r4                  ; r4‑‑ Dekrement
    ; ---------- Multiplikation ein‑Operand‑Form ----------
    mul r4                  ; r1 = r1 * r4; impliziter Operand r1; Ergebnis in r1; zerstört r1 und r3
    ; ---------- Multiplikation mehr‑Operand‑Form ----------
    mul r4, r2              ; r4 = r4 * r2 (zwei‑Operand, signierte Multiplikation, nur Zielregister verändert)
    mul r13, r1, 3          ; r13 = r1 * 3 (drei‑Operand‑Form)
    mul r14, r1, r2, r4     ; beliebig viele Operanden für Ketten‑Multiplikation
    mul r7, r1, r2, 5, r4
    der r3, 0               ; r3 (RDX) auf Null setzen
    ; ---------- Division ein‑Operand‑Form ----------
    div r2                  ; r1 = r1 / r2, r3 = r1 % r2; 128‑Bit‑Dividend aus r1:r3; vorzeichenlose Division
    ; ---------- Division mehr‑Operand‑Form ----------
    div r4, r2                          ; r4 = r4 / r2; Rest wird verworfen
    div r15, r1, r2                     ; r15 = r1 / r2
    div r16, r7, r1, r2                 ; r16 = r1 / r2, Rest kommt nach r7
    ; Hinweis mehr‑Operand div: vorzeichenlos; Divisor kann Register, Sofortwert oder Speicheradresse sein.
    ; ---------- Bit‑Operationen ----------
    und r1, 0xFF            ; r1 &= 0xFF Bit‑UND
    od  r4, r2              ; r4 |= r2 Bit‑ODER
    xod r1, 5               ; r1 ^=5 Bit‑XOR
    nich r1                 ; r1 = ~r1 Bit‑Negation
    ; ---------- Vergleich‑Befehl, Ergebnis landet in r3 ----------
    vgl r1, 10              ; vergleiche r1 und 10
                            ; r3 = 0 bei Gleichheit; 1 bei r1>10; ‑1 bei r1<10
    ; ---------- Bedingte Sprünge (abhängig von r3‑Ergebnis von vgl) ----------
    spr marke1              ; unbedingter Sprung
    sn  marke2              ; springe falls r3 ==0 (gleich)
    snn marke3              ; springe falls r3 !=0 (ungleich)
    sg  marke4              ; springe falls r3 ==1 (größer)
    sk  marke5              ; springe falls r3 ==‑1 (kleiner)
    sge marke6              ; springe falls r3 >=0 (größer‑gleich)
    ske marke7              ; springe falls r3 <=0 (kleiner‑gleich)
marke1:
    ; ---------- Unterprogramm‑Aufruf mit ruf und gib‑Rückkehr ----------
    ruf unterprog           ; Unterprogramm aufrufen; Rücksprung‑Adresse wird auf Stack abgelegt
    spr ende_s              ; zum Programm‑Ende springen
unterprog:
    ; ---------- Stack‑Operationen drk / hol ----------
    drk r1                  ; Register‑Wert auf Stack pushen
    hol r4                  ; Wert vom Stack in Register holen
    gib                     ; Rückkehr zum Aufruf‑Ort nach ruf
    ; ---------- Software‑Interrupt unt 0x80 ----------
    der r1, 1               ; Funktionscode 1: Prozess beenden
    unt 0x80
    ; ---------- Konsolen‑String‑Ausgabe zeig ----------
    zeig msg
    ; ---------- Programm‑Ende‑Befehl ende ----------
    ende
marke2:
marke3:
marke4:
marke5:
marke6:
marke7:
    ; Beispiel‑Zähl‑Schleife
    der r1, 0
schleife:
    vgl r1, 10
    sge ende_s
    ink r1
    spr schleife
ende_s:
    ende
    ; Zusätzliche Befehle
    ugib                    ; Interrupt‑Rückkehr; entspricht x86‑64 IRETQ
    in  r1, 0x60            ; Byte von IO‑Port 0x60 einlesen
    erg 0x60, r1            ; Byte‑Wert auf IO‑Port 0x60 ausgeben
; ============================================================================
; Hinweise zur VSE‑64‑Assembler‑Sprache
; 1. Der Einstiegspunkt ist fest _start; Ausführung läuft von oben nach unten; Sprünge ändern den Programm‑Counter.
; 2. Unterprogramme werden mit ruf aufgerufen und mit gib verlassen. Der Hauptcode darf kein gib benutzen; nutze ende zum Beenden.
; 3. Daten‑Labels (z.B. msg) sind nur für Speicher‑Zugriff / zeig‑Befehl gedacht, dürfen nicht als Sprung‑Ziel verwendet werden.
; 4. Bedingte Sprünge werten ausschließlich das Ergebnis aus dem vorherigen vgl‑Befehl in Register r3 aus.
; 5. Speicher‑Adressierung: [reg+versatz] oder [reg‑versatz]; versatz ist 64‑Bit‑Ganzzahl.
; 6. Zahlen: Dezimal‑ oder Hexadezimal‑Notation 0x…; immer 64‑Bit‑vorzeichenbehaftet.
; 7. Im Interpreter‑Modus unterstützt unt 0x80 nur Funktionscode 1 (Beenden) und 4 (Konsolen‑Ausgabe). Im kompilierten ‑c exe‑Modus werden zeig und ende zu WinAPI‑Aufrufen umgewandelt (nur Windows).
; ============================================================================
