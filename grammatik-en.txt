| Kernregel(.kr) Language Grammar Examples
| C++ VM‑type
| Uncomment the commented‑out code below to enable it (commented only to avoid extra output during testing)
| Function names, variable names and identifiers support Unicode characters
| For consistent syntax, avoid non‑default optional keywords
| Kr supports indentation‑style syntax (any indent deeper than parent block is valid); keep style consistent:
| if parent uses curly braces {}, child blocks must also use braces, otherwise syntax errors occur.
| Lexikal preprocessor does NOT support indent‑based syntax (preprocessing forbids ambiguity)
| Kr uses function scope; the für jedes loop creates new local scope; other loop constructs do not.
| All Kern code except memory operations is valid Kernregel code; execution behavior is nearly identical but logical semantics differ.
| VS Code syntax highlighting and lexikal semantic highlighting extensions are available.
| Semantic highlighting invokes the Kr interpreter to retrieve AST and token info, providing error diagnostics and identifier details.
|
| Without optimizations: empty loop ~4 ms for one‑million iterations; loop body with one increment ~17 ms, roughly equivalent to 100 million VA‑loop cycles.

/|
| When running a Kr program you may append arbitrary space‑separated arguments after script filename.
| These are automatically exposed as two global read‑only constants:
|
|   arga ‑ integer, count of passed arguments (excluding executable and script filename)
|   argw ‑ string array, each element holds one argument, zero‑based indexing
|
| Note: arga and argw are constants; reassignment is forbidden.
|
| Example shell invocation:
|   kr test.kr a b "c d"
|   → arga = 3, argw = ["a", "b", "c d"], fname() = "test.kr"
|
| Can combine with --opt:
|   kr test.kr --opt "{haupt: main}" arg1 arg2
|   main will be invoked, arga / argw still receive arg1 and arg2.
|
| Sample usage
|   fkt main() {
|       zeig "Script name: ", argw[0]
|       fa arga > 0 {
|           zeig "First argument: ", argw[1]
|       }
|       für i in 0..arga‑1 {
|           zeig "argw[", i, "] = ", argw[i]
|       }
|   }

        max_iter = 5

// Raw‑pointer & smart‑pointer utilities
/|
| Pointer type syntax: zgr<T> raw pointer; schlau<T> automatic‑lifetime smart pointer
| Built‑in pointer functions (usable as method calls):
|   zgr(value)           allocate copy of value on heap; return raw pointer
|   schlau(value)        allocate copy on heap; smart pointer auto‑deallocates
|   zgrw(ptr)            dereference read pointer
|   zgrs(ptr, value)     dereference write to pointer target
|   frei(ptr)            manually free raw pointer memory; smart pointers do not require frei
|   zgrNull(ptr)         test whether pointer is null‑pointer
|   ptr.typ()            returns string "zgr" or "schlau"
|/
x = 42

sp = schlau(x)              // Smart pointer copy

// zeig zgrw(p)             // 100
// zeig x                   // Original x unchanged (pointer holds copy)
frei(p)                     // Release raw pointer heap memory

// String interpolation syntax reference
// ────────────────────────────────────────────────────────────────
// Syntax rules:
//       {expr}                      evaluate expression and embed string representation
//       {expr:formatSpec}           invoke alt(formatSpec) on value
//       {expr:<width} / {expr:>width} / {expr:^width} alignment specifiers
//       {expr:fillChar<width}       custom padding character before alignment marker
//
// Alignment markers:
//   <    left‑align, pad right
//   >    right‑align, pad left
//   ^    center both‑side padding
//
// Backtick‑quoted strings use &{...} interpolation marker instead of {...}
// ────────────────────────────────────────────────────────────────
name2 = "World"
n = 42
s2 = "  Hello World!  "
// Basic interpolation examples
// zeig "Hello {name2}!"               → "Hello World!"
// zeig "2 + 2 = {2 + 2}"              → "2 + 2 = 4"
// zeig s2[2]                          // index string character access
// alt number formatting
// zeig "{n:.2k}"                      → "42.00" floating‑point two decimal places
// zeig "{n:16}"                       → "2A" hexadecimal output
// zeig "{n:04X}"                      → "002A" zero‑padded uppercase hex
// Alignment padding examples
// zeig "|{n:<8}|"                     → "|42      |" left‑align
// zeig "|{n:>8}|"                     → "|      42|" right‑align
// zeig "|{n:^8}|"                     → "|   42   |" centered
// zeig "|{n:*<8}|"                    → "|42******|" custom fill‑char asterisk
// zeig "|{n:‑^8}|"                    → "|---42---|" dash fill center
// zeig "|{n:0>4}|"                    → "|0042|" zero‑pad right‑align
// Combine format conversion + alignment
// zeig "|{n:16>8}|"                   → "|      2A|" hex then right‑pad
// zeig "|{n:.2k>10}|"                 → "|     42.00|" two decimal float then right‑pad
// Explicit method call for disambiguation when fill‑char would conflict with format spec
// zeig "|{n.füll(8, "l", "2")}|"      → "|22222242|"
// ANSI color escape inside interpolated strings
// zeig "{#FFFFFF} Text color. {#end}"      // reset with #end or #zurück
// zeig `&{name2}`                     // backtick‑string interpolation
// zeig `|&{n:<8}|`

// Embedded HTTP server starteServer / ac_starteServer
// Request‑object fields passed to handler function:
//   anfrage.methode  ‑ HTTP‑method string "GET", "POST", "PUT" etc
//   anfrage.pfad     ‑ full request‑path including query‑string
//   anfrage.kopf     ‑ object of request‑header key‑value pairs
//   anfrage.inhalt   ‑ raw unparsed request‑body string
// Handler function must return response‑object:
//   { zustand: httpStatusCode, kopf: { ...response‑headers... }, inhalt: responseBodyText }
// Built‑in response‑helper constructors auto‑set Content‑Type header:
//   html(text[, statusCode])        HTML response
//   json(value[, statusCode])       JSON‑serialize object as response
//   text(text[, statusCode])        plain‑text response
//   umleiten(url[, statusCode])     HTTP redirect response default status 302
// URL parsing helpers
//   abfrage(urlString)              parse query‑string into key‑value object
//   formular(postBody)              parse application/x‑www‑form‑encoded form data
//   esc(htmlText)                   HTML entity‑escape & < > " '
//   kodierURL(rawString)            URL percent‑encode string
//   dekodierURL(encodedString)      decode percent‑encoded URL component
// Server‑Sent‑Events SSE streaming API
//   SSE()                           create SSE stream‑handle object
//   sende(stream, data)             send plain SSE message
//   sendeSSE(stream, eventName, data) send named custom‑event SSE message
//   schliesse(stream)                terminate SSE stream connection
// Note: SSE data‑producer logic must live inside ac fkt async function to avoid blocking server‑worker thread.
// Network‑utility holeIP() retrieve host‑machine / client‑peer ip‑address information.
// Web‑server minimal GET‑route example:
fkt handler(anfrage) {
    url    = anfrage.pfad
    params = abfrage(url)
    qm     = url.stelleVon("?")
    pfad   = qm == ‑1 ? url : url.ab(0, qm)
    fa pfad == "/" {
        titel = params.titel ?? "World"
        gib html(`
            <!DOCTYPE html>
            <html lang="en">
            <head>
                <meta charset="utf‑8">
                <title>Kernregel</title>
                <style>
                    body { font‑family: sans‑serif; margin: 2em; }
                    h1   { color: #2a6; }
                    code { background: #eee; padding: 2px 4px; border‑radius: 3px; }
                </style>
            </head>
            <body>
                <h1>Hello &{esc(titel)}!</h1>
                <p>Path: <code>&{esc(pfad)}</code></p>
                <p>Search‑param: <code>&{esc(params.suche ?? "—")}</code></p>
                <ul>
                    <li><a href="/data?x=1&y=2">/data?x=1&y=2</a> (JSON)</li>
                    <li><a href="/text?name=Max">/text?name=Max</a> (Plain‑text)</li>
                    <li><a href="/old">/old</a> (Redirect → /)</li>
                </ul>
            </body>
            </html>
        `)
    }
    snfa pfad == "/data" {
        gib json({
            pfad: pfad,
            parameter: params,
            zeit: zeit(),
            gefunden: wahr
        })
    }
    snfa pfad == "/text" {
        gib text("Hello " ## (params.name ?? "World") ## "!\n")
    }
    snfa pfad == "/old" {
        gib umleiten("/", 302)
    }
    sonst {
        gib html(`
            <h1>404‑Not Found</h1>
            <p>Requested‑path: <code>&{esc(url)}</code></p>
        `, 404)
    }
}
starteServer(8080, handler)
// POST‑form‑handling web‑handler example
fkt formHandler(anfrage) {
    fa anfrage.pfad == "/login" und anfrage.methode == "GET" {
        gib html(`
            <form method="post" action="/login">
                <p>Username: <input name="username"></p>
                <p>Password: <input name="password" type="password"></p>
                <button type="submit">Sign‑in</button>
            </form>
        `)
    }
    snfa anfrage.pfad == "/login" und anfrage.methode == "POST" {
        daten  = formular(anfrage.inhalt)
        nutzer = daten.username ?? ""
        pass   = daten.password ?? ""
        fa nutzer == "" od pass == "" {
            gib text("Username and password required", 400)
        }
        fa nutzer == "admin" und pass == "secret" {
            gib umleiten("/welcome?name=" ## kodierURL(nutzer), 303)
        }
        gib html("<p>Login‑failed</p>", 401)
    }
    snfa anfrage.pfad == "/welcome" {
        name = abfrage(anfrage.pfad).name ?? "Guest"
        gib html("<h1>Welcome, &{esc(name)}!</h1>")
    }
    sonst {
        gib text("Method‑not‑supported", 405)
    }
}

; VSE Standard Architecture‑64 (.va) assembly syntax reference
; Comments start with semicolon
; Project started: 2026‑08‑24
; ============================================================================
; ----------------------------------------------------------------------------
; Register names (case‑insensitive)
;   r1  = RAX   r2  = RCX   r3  = RDX   r4  = RBX
;   r5  = RSP   r6  = RBP   r7  = RSI   r8  = RDI
;   r9  = R8    r10 = R9    r11 = R10   r12 = R11
;   r13 = R12   r14 = R13   r15 = R14   r16 = R15
; ----------------------------------------------------------------------------
; ---------- Static data definitions ----------
msg:    db "Hello World!", 0      ; zero‑terminated C‑style string
puffer: dq 0, 0, 0, 0            ; 32‑byte buffer for memory‑addressing demo
zahl:   dq 42                    ; 64‑bit integer constant
hexwer: db 0xFF, 0x0A            ; two raw byte values: 255 and 10
arr:    dd 1, 2, 3, 4            ; four 32‑bit integer entries
wort:   dw 0x1234                ; 16‑bit word constant
; ---------- Program entry‑point label (fixed _start) ----------
_start:
    ; ---------- Move / load‑store (der mnemonic) ----------
    der r1, puffer          ; r1 = runtime memory address of label puffer
    der r2, 100             ; load immediate constant value into register r2
    der [r1], r2            ; *(int64*)r1 = r2 ; memory store
    der r3, [r1]            ; r3 = *(int64*)r1 ; memory load
    ; Memory operand with offset displacement
    der r2, 200
    der [r1+8], r2
    der r4, [r1+8]          ; r4 = 200
    ; ---------- Arithmetic instructions ----------
    add r1, 3               ; r1 += 3
    sub r4, r2              ; r4 -= r2
    ink r1                  ; r1++ increment register
    dek r4                  ; r4-- decrement register
    ; ---------- Single‑operand multiply ----------
    mul r4                  ; r1 = r1 * r4; implicit source operand r1; destroys r1, r3 registers
    ; Note: single‑operand mul uses unsigned multiplication (mul r/m64 hardware). Clobbers r1 and r3.
    ; ---------- Multi‑operand signed multiply ----------
    mul r4, r2              ; r4 = r4 * r2          (two‑operand: dest = dest * src)
    mul r13, r1, 3          ; r13 = r1 * 3          (three‑operand: dest = src1 * src2)
    mul r14, r1, r2, r4     ; r14 = r1 * r2 * r4    (four+ operand chained‑multiplication)
    mul r7, r1, r2, 5, r4   ; r7 = r1 * r2 * 5 * r4
    ; Multi‑operand form uses signed imul instruction; only modifies destination register; r1 / r3 remain untouched.
    der r3, 0               ; zero r3 (RDX) register
    ; ---------- Single‑operand unsigned division ----------
    div r2                  ; r1 = r1 / r2 (quotient), r3 = r1 % r2 (remainder)
    ; Note: single‑operand div uses unsigned hardware div r/m64. Dividend is combined 128‑bit value r1:r3.
    ; ---------- Multi‑operand unsigned division ----------
    div r4, r2                          ; r4 = r4 / r2          (two‑operand; remainder discarded)
    div r15, r1, r2                     ; r15 = r1 / r2         (three‑operand; remainder discarded)
    div r16, r7, r1, r2                 ; r16 = r1 / r2         (four‑operand quotient‑output)
                                        ; r7 = r1 % r2          (four‑operand remainder‑output)
    ; Multi‑operand div uses unsigned hardware div; divisor saved temporarily on stack.
    ; Does not clobber arbitrary registers. First argument must be register for quotient output.

    ; Divisor operand can be register, 32‑bit immediate constant or memory reference.
